RK3588 是瑞芯微推出的高性能边缘计算板卡，用通俗易懂的话来说，它的性能就是"这机器能玩原神"。

先前在一个学长的指挥下我们部署过 YOLOv5，但当时并没有很详细的资料整理，也没想过复现。最近发现 26 年正点原子的 3588 板卡出了新资料，就决定直接用官方的 Debian 系统尝试移植先前的 YOLO26 手势识别项目。相比较 24 年的时候，现在有各种智能体的情况下，安装应该十分简单。我也会尝试一下官方给出的 DeepSeek 部署，或者自己创新量化一下阿里的 Qwen3（不过都是后话了，先给自己画饼，后续如果做了我也会放上过程）。

本来是打算直接写 3588 的 RKNN 量化和模型部署，但没有想到在一开始的系统烧录和 SSH 连接就踩坑了，所以先记录这两件事。后续关于 RKNN 量化优化以及部署其他模型都会再写一篇文章。

## 系统烧录

官方提供了四种系统：Buildroot、Debian、Ubuntu、Android。我更倾向于使用 Debian 13，因此本次用 Debian 13 作为板卡系统。当然如果想要其它系统也是可以上手移植的，比如可以尝试自行移植 Arch、NixOS，或者嵌入式设备上很多人喜欢的 Armbian，后续我也会尝试移植 Armbian。

我使用 Arch Linux 作为开发环境，不过本文仍然会讲一下通用流程。

### 下载镜像

官方百度网盘链接的目录：

```text
开发板光盘A盘-基础资料/正点原子】ATK-DLRK3588开发板网盘A盘-基础资料（2026最新版，推荐使用）/09、系统镜像/08、Linux6.12_debian13系统镜像
```

这个目录下有两个镜像：一个支持 MIPI + HDMI 显示、不支持 DP；另一个支持 DP + HDMI、不支持 MIPI 屏幕。区别在官方资料中有写，按自己的屏幕接口选即可。

### 安装烧录工具

RKDevelopTool-GUI 是社区为 rkdeveloptool 开发的跨平台图形界面前端，可用于固件烧录、分区管理和设备调试，同时也提供了 rkdeveloptool 的命令行，使用方便。

Arch 下的安装命令：

```bash
yay -S rkdeveloptool-gui
```

其它发行版参考项目地址 <https://github.com/gahingwoo/RKDevelopTool-GUI>：

```bash
curl -fsSL https://raw.githubusercontent.com/gahingwoo/RKDevelopTool-GUI/main/install.sh | sh
```

先打开 rkdeveloptool-gui。板卡关机状态下，使用 Type-C 线连接电脑与板卡的**第二个 Type-C 接口**，按住 UPDATE 按钮，上电即可正常连接到板卡。

此时提示我们需要先加载 Loader，点击"是"，再选择镜像烧录即可。

![选择镜像烧录](/covers/3588烧录&连接/烧录2.png)

### 踩坑：烧录一直提示超出磁盘配额

我在烧录时一直提示超出磁盘配额。原因是设备的 `/tmp` 交换分区过小——镜像在解包后会暂存在临时分区，我的分区大小不够。

解决办法有两种：调整分区大小，或者修改环境变量让软件使用其它目录作为临时目录。修改 `/tmp` 分区较为复杂同时相对危险，这里不做演示；而修改全局的 `TMPDIR` 环境变量又会导致整个系统使用其它目录作为 tmp。因此我决定做最小的修改：改我使用的 KDE 桌面环境的启动图标信息，让点击图标启动软件时通过 `.desktop` 文件带上独立的 `TMPDIR`。

#### 修改 .desktop 文件

系统级的 `.desktop` 文件在 `/usr/share/applications` 下：

```bash
sudo vim /usr/share/applications/io.github.gahingwoo.rkdeveloptool_gui.desktop
```

```ini
[Desktop Entry]
Type=Application
Name=RKDevelopTool GUI
Comment=Flash and manage Rockchip devices
# Exec=rkdeveloptool-gui
Exec=/usr/bin/env TMPDIR=/home/long/.rkfw_tmp /usr/bin/rkdeveloptool-gui
Icon=rkdeveloptool-gui
Categories=Development;
Keywords=Rockchip;rkdeveloptool;firmware;flash;maskrom;partition;
Terminal=false
```

我把第五行的 `Exec=rkdeveloptool-gui` 改为：

```ini
Exec=/usr/bin/env TMPDIR=/home/long/.rkfw_tmp /usr/bin/rkdeveloptool-gui
```

指定 `TMPDIR=/home/long/.rkfw_tmp` 后，修改成功，重启软件即可正常烧录。

更推荐用户级方案，只对当前用户生效，文件应该在 `~/.local/share/applications` 下：

```bash
vim ~/.local/share/applications/io.github.gahingwoo.rkdeveloptool_gui.desktop
```

文件内容与 `/usr` 目录下相同。记得先 `mkdir -p ~/.local/share/applications` 并给临时目录建好文件夹。

## VSCode 远程连接

在使用 VSCode 连接之前，需要先用命令行连接，并在板卡上安装一些对应的软件包，否则 VSCode 的 SSH 服务无法正常安装，一定会出现连接失败的问题。

### 命令行先连上板卡

```bash
# ssh 用户名@ip地址
ssh rockchip@192.168.3.89
```

其中 `192.168.3.89` 是我这里板卡的 IP 地址，请根据自身实际情况修改。设备 IP 可以通过查看路由器获得，或者连接显示器后键盘输入 `ip a` 查看。

![ssh 连接板卡](/covers/3588烧录&连接/ssh连接.png)

### 板卡安装对应服务

```bash
sudo apt-get update
sudo apt-get install -y libnss3 libatk1.0-0 libatk-bridge2.0-0 libcups2 \
  libdrm2 libxkbcommon0 libxcomposite1 libxdamage1 libxfixes3 libxrandr2 \
  libgbm1 libasound2
```

### 修改板卡时区为Shanghai,China，中文语言（可选）或使用mipi屏幕可以直接通过触摸屏修改

```bash
# 直接修改时区为上海/Shanghai
sudo timedatectl set-timezone Asia/Shanghai
# 验证时区是否修改成功
timedatectl
date
```

### VSCode 连接

安装后打开 VSCode，安装 Remote - SSH 插件，在左侧的 SSH 连接窗口上点击加号，在弹出的窗口输入 ssh 连接命令。

![添加 SSH 连接](/covers/3588烧录&连接/vs连接1.png)

![输入连接命令](/covers/3588烧录&连接/vs连接2.png)

等待一段时间 VSCode-SSH 服务安装后，会提示输入板卡系统的密码，输入密码后即正常连接到板卡。

![输入密码](/covers/3588烧录&连接/enter_passwd.png)

## 小结

- 烧录走 MaskROM/Loader 流程：第二个 Type-C 口 + 按住 UPDATE 上电。
- `/tmp` 太小导致烧录报磁盘配额错误，最小改动的解法是给 `.desktop` 的 `Exec` 单独指定 `TMPDIR`。
- VSCode Remote-SSH 之前，务必先在板卡上 `apt-get install` 那一串依赖库。
